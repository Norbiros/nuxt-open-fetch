Clients are generated for each OpenAPI client specified in the `openFetch` section of Nuxt config and provide a convenient wrapper around [`$fetch`][nuxt#$fetch].

## Usage

You can access clients from the Vue context using `useNuxtApp()`.

It has the same API as Nuxt's [`$fetch`][nuxt#$fetch] util with an additional `path` option, which is used to replace params in the pathname.
For other options, see [additional parameters](#additional-parameters).

```vue
<script setup lang="ts">
const { $pets } = useNuxtApp()

const data = await $pets('/pet/{petId}', {
  path: {
    petId: 12
  }
})
</script>

<template>
  <h1>{{ data?.name }}</h1>
</template>
```

or inside a Nitro handler:

```ts [server/api/pet.get.ts]
export default defineEventHandler(async () => {
  const { $pets } = useNitroApp()

  return await $pets('/pet/{petId}', {
    path: {
      petId: 12
    }
  })
})
```

## Raw response

Like [`$fetch.raw`](https://github.com/unjs/ofetch#%EF%B8%8F-access-to-raw-response), each client exposes a `raw` method returning the raw `Response` with a typed `_data` body — useful for accessing the status code or response headers:

```ts
const { $pets } = useNuxtApp()

const response = await $pets.raw('/pet/{petId}', {
  path: {
    petId: 12
  }
})

console.log(response.status)
console.log(response.headers.get('content-type'))
console.log(response._data?.name)
```

It accepts exactly the same arguments and options as the regular client call.

## Derived clients

Like [`$fetch.create`](https://github.com/unjs/ofetch#%EF%B8%8F-create-fetch-with-default-options), each client exposes a `create` method returning a new, equally typed client with the given options preset — useful for example for an authenticated variant of a client:

```ts
const { $pets } = useNuxtApp()

const authedPets = $pets.create({
  headers: {
    Authorization: `Bearer ${token}`
  }
})

const pet = await authedPets('/pet/{petId}', {
  path: {
    petId: 12
  }
})
```

The preset options are merged with the client's configuration (headers included), per-call options still take precedence, and everything else — path parameter replacement, [hooks](/advanced/hooks), `raw`, further `create` calls — keeps working on the derived client.

Options that change the OpenAPI operation or its response type (`method`, `body`, `parseResponse`, and `responseType`) must be provided on each request and cannot be preset with `create`.

## Additional parameters

In addition to the [`$fetch`][nuxt#$fetch] options, the client accepts the following additional parameters:

### `path`

- **Type:** `Record<string, string | number>`

The exact type of the `path` is generated from the OpenAPI schema for type safety and autocompletion.
This option lets you replace the path parameters in the endpoint URL with the actual values.

### `accept`

- **Type:** `MediaType | MediaType[]`

The exact type of the `accept` option is generated from the available response types in the OpenAPI schema.
This option allows you to set the `Accept` header for the request and typeset the result type accordingly.

::warning
The value of the `accept` option will always override the `Accept` header sent by the client, even if overridden in the `$fetch` options.
::

For more examples, see [Response types](../advanced/response-types).

[nuxt#$fetch]: https://nuxt.com/docs/api/utils/dollarfetch

### `bodySerializer`

- Type: `(body: RequestBody) => any`

Allows modifying the body before it gets used in the request. Mostly needed when
working with `multipart/form-data`:

```typescript
const { $pets } = useNuxtApp()

const data = await $pets('/pet', {
  method: 'POST',
  body: {
    name: 'Doggie',
    photoUrls: []
  },
  bodySerializer(body) {
    const formData = new FormData()
    for (const [key, value] of Object.entries(body)) {
      formData.append(key, String(value))
    }
    return formData
  }
})
```
